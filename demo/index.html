<form-required-checkboxes>

Require an exact count, a range, or an optional maximum of native checkbox selections. See the README for installation and API documentation.

Read the README View on GitHub esm.sh example unpkg example

Your choice is saved for other component demos on this site that support tabs.

The checkboxes work before enhancement. Selection-count validation needs JavaScript; if the module doesn’t load, follow the limits in each legend. Applications must also validate selections on the server.

Require an exact count

Set required="3" on the component to require exactly three selections. Wrap labeled, same-name checkboxes in a fieldset with a legend.

Submit with fewer or more than three selections to see the browser’s validation message. The browser can focus the first checkbox; changing a checkbox clears the custom error. Reset restores selections and clears the component’s custom error. Canceling a reset preserves the existing state.

Native required on an individual checkbox requires that checkbox, not a count across the group. Other invalid fields can stop native submission before group validation runs. See the required-email example.

Choose three skills

Code

<script type="module" src="../define.js"></script>

<form-required-checkboxes required="3">
  <fieldset>
    <legend>Choose your top 3 skills</legend>
    <label> <input type="checkbox" name="skills[]" value="js"> JavaScript </label>
    <!-- options continue -->
  </fieldset>
</form-required-checkboxes>

Include a required native field

Match your application’s vocabulary

Set notice-message and error-message for one group. These complete phrases refer to colors rather than generic choices. Tokens follow the current limits. For the full precedence rules, see localization.

The legacy notice and error attributes and properties are deprecated and will be removed in a future major release. Use the *-message attributes shown here (or their noticeMessage and errorMessage properties), or move page-wide strings to shared JSON configuration. Remove legacy overrides when using shared messages; otherwise, they still take precedence.

Code

<form-required-checkboxes 
  required="3" 
  notice-message="Pick exactly {n} colors you like"
  error-message="You must select exactly {n} colors">
  <fieldset>
    <legend>Favorite colors (choose exactly 3)</legend>
    <label> <input type="checkbox" name="colors[]" value="red"> Red </label>
    <!-- options continue -->
  </fieldset>
</form-required-checkboxes>

Share wording across groups

One authored JSON script supplies page defaults. These two groups share a range message; the second overrides only its notice. Missing rules retain their fallback messages. Changing the JSON takes effect when you call refresh().

Code

<script type="application/json" data-form-required-checkboxes-config>
{
  "notice-message": { "range": "Choose {min}–{max} options." }
}
</script>

<form-required-checkboxes required="1-2">
  <fieldset>
    <legend>Choose 1–2 meeting days</legend>
    <label><input type="checkbox" name="meeting-days" value="mon"> Monday</label>
    <!-- options continue -->
  </fieldset>
</form-required-checkboxes>

Read state and update limits

Use the read-only checkedCount, valid, and enhanced properties instead of inspecting generated markup. A change event reports changed outcomes, without exposing selected values. Updating required preserves selections and focus; setters don’t dispatch that event.

Code

<form>
  <form-required-checkboxes id="state-group" required="1-2">
    <fieldset>
      <legend>Choose 1–2 skills, or allow up to three</legend>
      <label><input type="checkbox" name="state-skills" value="html" checked> HTML</label>
      <!-- options continue -->
    </fieldset>
  </form-required-checkboxes>
  <p id="group-state" role="status" hidden
     data-message="{count} selected. {validity}"
     data-valid-message="Within the limits."
     data-invalid-message="Adjust your selection."></p>
  <button type="button" data-allow-three>Allow up to three</button>
  <button type="reset">Reset selections</button>
</form>
<script type="module">
import '../define.js';
const group = document.querySelector('#state-group');
const output = document.querySelector('#group-state');

function showState() {
  const validity = group.valid
    ? output.dataset.validMessage
    : output.dataset.invalidMessage;
  output.textContent = output.dataset.message
    .replace('{count}', String(group.checkedCount))
    .replace('{validity}', validity);
  output.hidden = false;
}
group.addEventListener('form-required-checkboxes:change', showState);
if (group.refresh()) showState();

document.querySelector('[data-allow-three]').addEventListener('click', () => {
  group.required = '1-3';
  showState(); // Property assignment is silent.
});
</script>

Translate group messages

Author messages in the page’s language and use lang for number formatting. Translate the legend, labels, buttons, and result text too. These example forms are translated; the surrounding tutorial and shared code controls remain in English. Built-in translations remain available but are deprecated in favor of authored strings.

Code

  required="2-4"

  error-message="Debe elegir entre {min} y {max} opciones">
